    **1. Create `WindowShell.tsx`** (per UI-SPEC Component 8 -- portal-specific, NOT the shared GlassWindow):

    This is a custom portal component. Do NOT use the shared `GlassWindow` from `@hyperquote/ui` -- that component is a full-screen overlay designed for the internal platform. The portal's WindowShell needs a centered panel over a visible receded canvas.

    Props:
    ```typescript
    interface WindowShellProps {
      title: string        // i18n-resolved title
      subtitle?: string    // optional subtitle
      children: ReactNode
    }
    ```

    Structure:
    - Fixed overlay (`fixed inset-0 z-40 flex items-center justify-center`)
    - Backdrop: semi-transparent overlay (`bg-black/20 dark:bg-black/40`) that covers canvas. Clicking backdrop navigates to `/` (closes window).
    - Window panel: `motion.div` with:
      - Initial: `{ opacity: 0, scale: 0.98 }`
      - Animate: `{ opacity: 1, scale: 1 }`
      - Transition (enter): `{ type: 'spring', stiffness: 200, damping: 20 }`
      - Exit: handled by AnimatePresence in a wrapper (see below)
      - Max-width: 1200px (`max-w-[1200px]`)
      - Max-height: 90vh (`max-h-[90vh]`)
      - Width: `w-[95vw] md:w-[90vw]`
      - Surface: `bg-[var(--color-card)] backdrop-blur-xl bg-opacity-80` -- use explicit rgba: `bg-[rgba(255,255,255,0.80)] dark:bg-[rgba(0,0,0,0.80)]`
      - `rounded-3xl shadow-2xl`
      - Border: `border border-[var(--color-border)]/50`
    - Header bar (per spec): h-56px (h-14), px-24px (px-6), border-bottom
      - Left: title (Inter 600 18px) + subtitle (Inter 400 14px muted)
      - Right: close button (X icon 24px, 44px touch target). `aria-label={t('window.close')}`
      - Close navigates to `/` via `useNavigate()` from `@tanstack/react-router`
    - Content area: `overflow-auto flex-1` below header

    **Exit animation challenge:** TanStack Router unmounts route components on navigation. To get tween exit (opacity 1->0, 150ms), the WindowShell needs to stay mounted briefly.

    **Solution:** Wrap WindowShell content with AnimatePresence inside the component. The window IS always rendered when the route matches, and AnimatePresence handles the enter animation. For exit, since the Router unmounts the component, the exit animation will be handled by the backdrop/canvas restore animation (tween 300ms back to normal). This is acceptable -- the canvas restoration IS the exit visual feedback.

    Alternatively, implement a route transition wrapper. The simplest approach that actually works:
    - In the `_portal.tsx` layout, wrap `<Outlet />` with a component that detects route changes and manages AnimatePresence.
    - Use a `key` prop on the window content based on route pathname.
    - This way AnimatePresence can animate exit before unmount.

    The recommended pattern:
    ```typescript
    // In _portal.tsx layout, add around Outlet:
    <WindowAnimationWrapper>
      <Outlet />
    </WindowAnimationWrapper>
    ```
    Where `WindowAnimationWrapper` uses `useLocation()` to detect window routes and wraps content in `AnimatePresence mode="wait"`. When the route changes from `/orders` to `/`, AnimatePresence plays exit on the window before mounting the canvas-only view.

    If this proves too complex, skip exit animation on the window panel itself and rely on canvas restore (opacity 0.5->1, blur 2px->0px) as the visual feedback for window close. Document the tradeoff.

    **Keyboard: Escape closes window:**
    - Use `useShortcut('Escape', () => navigate({ to: '/' }))` inside WindowShell
    - This fires only when a window is open (WindowShell is mounted)

    **Mobile (<768px) per spec:**
    - Full-screen: `md:max-w-[1200px] md:max-h-[90vh] md:rounded-3xl max-md:w-full max-md:h-full max-md:rounded-none`
    - Slides up from bottom: initial `{ y: '100%' }` on mobile, `{ scale: 0.98 }` on desktop
    - Detect via CSS or `window.matchMedia` -- prefer CSS-driven approach
