# Phase 9 -- UI Design Contract

> Visual and interaction contract for Portal Material List Builder + Quote Submission: 3-step flow (Build -> Details -> Review), 4 input methods (Search & Add, CSV/Excel Upload, Quick Pad, AI Assist), buyer-side approval workflows. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none (shadcn excluded per CLAUDE.md -- React Aria mandated) |
| Preset | not applicable |
| Component library | React Aria Components ^1.16.0 |
| Icon library | Lucide React |
| Font | Inter (Latin), IBM Plex Sans Arabic (Arabic), Geist Mono (all numbers) |

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline element padding, badge internal gap |
| sm | 8px | Row gaps, chip outer gap, compact spacing, tab gap |
| md | 16px | Card padding, section padding, form field gaps |
| lg | 24px | Window internal horizontal padding, step section gaps |
| xl | 32px | Major layout gaps, step transition spacing |
| 2xl | 48px | Confirmation view vertical padding |
| 3xl | 64px | Not used in this phase |

Exceptions: 44px minimum touch target for all buttons (Continue, Submit, Parse with AI, file browse, date picker trigger, address ComboBox). 52px product list row height. 36px compact input fields (quantity, notes, tab height). 56px back-button row height. 200px upload drop zone height. 80px quantity field width. 160px notes field width. 400px max-width for Submit button. 640px implied max-width from glass window content area. 12px card margins and info banner padding. 20px step indicator connecting line gap.

## Typography

| Role | Size | Weight | Line Height | Font |
|------|------|--------|-------------|------|
| Body / Form labels / Table cells | 14px | 400 | 1.5 | Inter / IBM Plex Sans Arabic |
| Small / Meta / Tab labels / Helpers | 12px | 400-500 | 1.5 | Inter / IBM Plex Sans Arabic |
| Heading (window title, confirmation) | 18px | 600-700 | 1.2 | Inter / IBM Plex Sans Arabic |
| Numbers (quantities, item counts, dates, reference IDs) | 12-16px | 400 | 1.5 | Geist Mono |

Distinct sizes: 12px, 14px, 16px, 18px (4 sizes, 2 weights: 400 + 600). Exception: 700 on confirmation heading "Quote Request Submitted!" per FRONTEND.md, and 13px on tab labels and card descriptions per FRONTEND.md.

Notes:
- Portal base is 14px (not 16px -- apps per UI-VISION.md).
- Geist Mono for ALL numeric data: row numbers, quantities, UOM step values, item counts, dates, reference numbers (QR-2026-XXXXX), file sizes, progress percentages, validation counts ("247 of 250").
- Arabic-Indic numerals when locale is Arabic. No exceptions.
- Step indicator numbers: Geist Mono 12px inside 24px circles.
- Tab count badges: Geist Mono 12px.

## Focal Point

Primary focal point: **product list table** -- the material list is the entire purpose of this phase. All 4 input methods feed items into this single table. The table is always visible during Step 1 regardless of which input method is active above it. Secondary focal point: **Submit button** on Step 3, the culmination of the 3-step flow.

## Component Inventory

### 1. Step Indicator
- 3 steps: "Build List" -> "Details" -> "Review". Horizontal bar with circles.
- Each step: 24px circle with step number (Geist Mono 12px).
- Active: `var(--color-primary)` bg, white text.
- Completed: `var(--color-success)` bg, white Lucide `Check` 14px.
- Upcoming: `var(--color-border)` bg, `var(--color-text-muted)` text.
- Connecting line between steps: 2px height, `var(--color-primary)` for completed segments, `var(--color-border)` for upcoming.
- Step label below circle: Inter 500 12px.
- Mobile: numbers only, no labels.

### 2. Back Button Row
- "< Back to Orders": Lucide `ArrowLeft` 16px + text, Inter 500 14px `var(--color-text-muted)`.
- Flips to `ArrowRight` in RTL.
- Height 56px total row. Click returns to Orders tab view.

### 3. Input Method Tabs
- React Aria `Tabs`, compact. 4 tabs: "Search & Add" (default), "Upload", "Quick Pad", "AI Assist".
- Each tab: h-36px, Inter 500 13px.
- Inactive: `var(--color-text-muted)`. Active: `var(--color-text)` + 2px bottom border `var(--color-primary)`.
- Tab content area switches below; product list table persists below all methods.

### 4. Search & Add (Method 1)
- React Aria `ComboBox` with `Autocomplete`. Full width, h-44px.
- Lucide `Search` 16px inline-start. Placeholder: "Search for materials..." / "ابحث عن المواد...".
- Debounce: 150ms.
- Dropdown: max 8 visible results, scrollable. Each item: product name (Inter 400 14px) + category badge (12px, rounded-full, `var(--color-surface)` bg, `var(--color-text-muted)` text, px-8px py-2px) + availability dot (6px circle, green/red).
- On select: item added to product list, focus moves to quantity field.

### 5. Product List Table
- Columns: "#" (row number, Geist Mono 12px) | "Product" (name + SKU) | "Qty" (editable) | "UOM" (read-only) | "Notes" (optional) | "Actions" (delete).
- Each row: h-52px. Border-bottom 1px `var(--color-border)`.
- Row drag handle: Lucide `GripVertical` 16px, `var(--color-text-subtle)` at inline-start. React Aria `useDrag`/`useDrop`.
- Quantity: React Aria `NumberField`, 80px width, h-36px, Geist Mono. Min 1. Step by product UOM.
- Notes: React Aria `TextField`, 160px width, h-36px. Placeholder: "Optional notes" / "ملاحظات اختيارية".
- Delete: Lucide `Trash2` 16px, `var(--color-text-muted)`, hover `var(--color-error)`. Row removed immediately (no confirmation). Tween fade-out.
- Empty table: "No items yet. Search for materials above." / "لا توجد عناصر بعد. ابحث عن المواد أعلاه."
- Mobile: card layout (one card per item, stacked fields). No drag reorder on mobile.

### 6. Upload Zone (Method 2)
- Drag-and-drop zone: 200px height, border 2px dashed `var(--color-border)`, rounded-xl, centered content.
- Icon: Lucide `Upload` 32px `var(--color-text-subtle)`.
- Primary text: "Drop your file here or click to browse" / "اسحب ملفك هنا أو انقر للتصفح" -- Inter 400 14px `var(--color-text-muted)`.
- Secondary text: "Supports: CSV, Excel (.xlsx), PDF" / "يدعم: CSV، Excel (.xlsx)، PDF" -- Inter 400 12px `var(--color-text-subtle)`.
- "Download Template" link: below drop zone. Inter 400 12px `var(--color-primary)`. Downloads CSV with headers (Product Name, SKU, Quantity, UOM, Notes).
- Processing state: file icon + filename + progress bar (NOT spinner), Geist Mono percentage. "Parsing your file..." / "جاري تحليل ملفك..."
- Drag hover: border-color `var(--color-primary)`, bg `var(--color-info-bg)` at 50% opacity.
- Mobile: larger drop zone, easier tap target.

### 7. Upload Validation & Error Table
- All errors shown at once. Never fail on first error.
- Progress text: "{N} of {M} items validated successfully. {X} need attention." -- Geist Mono for numbers.
- Error table: row number (Geist Mono) | field name | value found | expected value. Border 1px `var(--color-border)`, rounded-xl.
- Error rows: `var(--color-error-bg)` background tint.
- Actions: "[Fix & Continue]" (blue outline, h-36px) and "[Re-upload]" (outline, h-36px).
- Unmatched items in product list: yellow warning badge "Unmatched -- please verify" / "غير مطابق -- يرجى التحقق" (12px 500, `var(--color-warning)` text, `var(--color-warning-bg)` bg, rounded-full, px-8px py-2px) + dropdown ComboBox to manually select product.

### 8. Quick Pad (Method 3)
- Spreadsheet-style grid: 3 columns -- SKU/name input (ComboBox, 60% width) + Quantity (NumberField, 20% width) + UOM display (20% width, auto-populated, read-only).
- 10 empty rows by default. More rows appear as user fills.
- Tab key flow: SKU -> auto-populate -> Qty -> next row SKU (skip auto-populated).
- Enter: adds one item. Ctrl+Enter: adds all valid items.
- Multi-SKU paste: one per line or tab/comma-separated.
- SKU validation: 300ms debounce. Invalid: red border + inline error 12px `var(--color-error)`.
- Mobile: one row at a time (single-row input mode).

### 9. AI Assist (Method 4)
- React Aria `TextArea`, 6 rows, full width. Placeholder: "Describe what you need in your own words..." / "اكتب ما تحتاجه بكلماتك..."
- Example text below: "Example: I need 500 bags of OPC cement 50kg, 200 bundles of 12mm rebar, and 100 sheets of 18mm plywood" -- Inter 400 12px `var(--color-text-subtle)`.
- "Parse with AI" button: blue bg, h-44px, Inter 600 14px white text, rounded-xl. Lucide `Sparkles` 16px inline-start.
- Processing: button shows "Parsing..." / "جاري التحليل...". Parsed results populate product list.
- AI clarification: mini-chat inline. Question text (14px 400) + option buttons (blue outline, h-32px, 12px 600).
- Unmatched items flagged same as upload method.

### 10. Project Assignment
- React Aria `ComboBox` with create option. Label: "Project (optional)" / "المشروع (اختياري)".
- Lists existing projects. Type new name -> "Create project: {name}" option at dropdown bottom.
- Position: below product list table, before action buttons.

### 11. Step 1 Action Bar
- Left: "{N} items in your list" / "{N} عناصر في قائمتك" -- Geist Mono for N, Inter 400 14px.
- "Save as Draft" button: outline border, h-40px, px-16px, rounded-lg. Toast: "Draft saved" / "تم حفظ المسودة".
- "Continue" button: blue bg, h-44px, px-24px, Inter 600 14px white text, rounded-xl. Disabled if list empty (opacity 0.5, pointer-events none).
- Validation on Continue: all items must have qty >= 1. Invalid rows: red border highlight.

### 12. Delivery Address (Step 2)
- React Aria `ComboBox`. Label: "Delivery Location" / "موقع التسليم". Lists saved addresses.
- "Add New Address" option expands inline fields: Street, Area/District, City/Governorate (React Aria `Select` with 27 Egyptian governorates), Landmark (optional), Phone at site (optional).
- First-time behavior: if zero saved addresses, ComboBox hidden. "Add your delivery address" heading (Inter 600 16px). Address form auto-expanded.
- Required: Street, Area, City/Governorate. Optional: Landmark, Phone.

### 13. Delivery Date (Step 2)
- React Aria `DatePicker`. Label: "Preferred Delivery Date" / "تاريخ التسليم المفضل". Geist Mono for date display.
- Min date: tomorrow. Business day validation: Friday/Saturday blocked.
- Error if non-business day: "Friday is not a delivery day. Please choose Sunday-Thursday." / "الجمعة ليست يوم تسليم. يرجى اختيار من الأحد إلى الخميس." -- 12px `var(--color-error)`.

### 14. Notes & Attachments (Step 2)
- Notes: React Aria `TextArea`, 3 rows. Label: "Notes to HyperQuote" / "ملاحظات لهايبر كوت". Optional.
- File attachments: drop zone for drawings/specs (PDF, images). Max 5 files, 10MB each.
- Uploaded files as chips: filename + Lucide `X` to remove. 12px, `var(--color-surface)` bg, rounded-full, px-8px py-4px.
- Step 2 navigation: "Back" (outline, h-40px) + "Continue" (blue, h-44px).

### 15. Review Summary (Step 3)
- Read-only item table: Product | Qty | UOM | Notes. Geist Mono for numeric columns.
- Delivery details section: address, date, notes. Attached files listed.
- Project name if assigned.
- "Edit" links: Lucide `Pencil` 14px + "Edit" / "تعديل" text, `var(--color-primary)`. Navigate back to relevant step.
- Info banner: "Prices are not shown here. We'll prepare a quote for you." / "الأسعار غير معروضة هنا. سنقوم بتجهيز عرض سعر لك." -- `var(--color-info-bg)` bg, `var(--color-info)` text, rounded-lg, p-12px.

### 16. Submit Button (Step 3)
- "Submit Quote Request" / "إرسال طلب عرض السعر": full width max 400px, centered, blue bg, white text, Inter 600 16px, h-52px, rounded-xl, shadow-sm.
- On click: opens confirmation modal.

### 17. Confirmation Modal (Elevated Glass)
- "Submit quote request for {N} items?" / "إرسال طلب عرض سعر لعدد {N} عناصر?" -- Inter 600 18px. Geist Mono for N.
- "We'll prepare your quote within 4 hours." / "سنقوم بتجهيز عرض السعر خلال ٤ ساعات." -- Inter 400 14px muted.
- "Cancel" (outline, h-40px) + "Submit" (blue, h-40px).
- On Submit: button shows "Submitting..." / "جاري الإرسال...". Skeleton replaces form.

### 18. Success Confirmation View
- Lucide `CheckCircle` 48px `var(--color-success)`. Spring animation.
- "Quote Request Submitted!" / "تم إرسال طلب عرض السعر!" -- Inter 700 24px.
- "Reference: QR-2026-{XXXXX}" / "المرجع: QR-2026-{XXXXX}" -- Geist Mono 16px `var(--color-primary)`.
- "We'll have your quote ready within 4 hours. You'll receive a notification on WhatsApp." / "سيكون عرض السعر جاهز خلال ٤ ساعات. ستتلقى إشعار على واتساب." -- Inter 400 14px muted.
- "Track Quote" button (blue, h-44px, rounded-xl) -- opens quote in Active tab.
- "Back to Orders" link (Inter 400 14px `var(--color-primary)`).

### 19. Buyer-Side Approval Flow (PORT-13)
- When a Buyer (non-approver) submits: "Submit for Approval" replaces "Submit Quote Request" button. Same styling (blue, h-52px, 400px max, centered).
- Confirmation modal text changes: "Submit for approval? Your team approver will review this request." / "إرسال للموافقة؟ سيراجع المعتمد في فريقك هذا الطلب."
- Success view text changes: "Submitted for Approval!" / "تم الإرسال للموافقة!" + "Your approver will be notified." / "سيتم إخطار المعتمد."
- Pending approvals: visible in Orders window "Active" tab with status badge "Pending Approval" (yellow/warning).
- Approver notification: in-app notification bell badge. Notification card: "Ahmed submitted a quote request for {N} items" + "Review" button (blue outline, h-32px).
- Approver actions: on the quote request detail, approver sees "Approve & Submit" (blue, h-44px) + "Request Changes" (outline, h-40px). "Approve & Submit" sends to HyperQuote. "Request Changes" returns to buyer with optional note.

### 20. Auto-Save Draft Indicator
- Auto-save every 30 seconds to localStorage. Server draft save secondary.
- Indicator: "Draft saved" / "تم حفظ المسودة" -- 12px 400 `var(--color-text-subtle)`, appears briefly (2s fade, tween) near Step 1 action bar.
- On return to in-progress draft: "Continue where you left off?" / "متابعة من حيث توقفت؟" banner at top of builder. "Continue" (blue outline, h-36px) + "Start Fresh" (text link, 12px `var(--color-text-muted)`).

## Icon-Only Button Declaration

The following buttons are intentionally icon-only at all breakpoints:

| Button | Icon | Rationale |
|--------|------|-----------|
| Delete row | Trash2 | Contextual within table row; action column provides context |
| Drag handle | GripVertical | Universal drag affordance; positioned at row inline-start |
| Remove attachment | X | Universal close/remove affordance; positioned on file chip |

All other buttons in this phase render visible text labels. Delete, drag, and remove rely on `aria-label` for screen reader access and universally-recognized icons for sighted users.

Tooltip spec (same as Phase 8): appears after 500ms hover delay (desktop) or long-press (mobile). Tween entrance: opacity 0->1, 150ms. Background `var(--color-card)`, border 1px `var(--color-border)`, rounded-lg, px-8px py-4px, 12px 400, shadow-sm.

## Accessibility Contract

- All interactive elements: 44px minimum touch target
- Focus visible: 2px offset ring using `var(--color-primary)` at 50% opacity
- Step indicator: `role="navigation"`, `aria-label="Quote request steps"` / `aria-label="خطوات طلب عرض السعر"`, current step `aria-current="step"`
- ComboBox (search, address, project): React Aria manages `role="combobox"`, `aria-expanded`, `aria-activedescendant`
- Product list table: `role="table"`, `aria-label="Material list"` / `aria-label="قائمة المواد"`
- Delete button: `aria-label="Remove {product name}"` / `aria-label="إزالة {product name}"`
- Drag handle: `aria-label="Reorder {product name}"` / `aria-label="إعادة ترتيب {product name}"`
- NumberField (quantity): React Aria manages increment/decrement, `aria-label="Quantity for {product name}"`
- DatePicker: React Aria manages calendar navigation, business day validation surfaced as `aria-describedby` error
- Upload zone: `role="button"`, `aria-label="Upload file"` / `aria-label="رفع ملف"`, file input hidden, triggered on click/drop
- Confirmation modal: React Aria Dialog, focus trapped, Escape dismisses, `isKeyboardDismissDisabled` on confirmation actions
- Progress bar (upload): `role="progressbar"`, `aria-valuenow`, `aria-valuemin="0"`, `aria-valuemax="100"`
- Screen reader: announce step transitions via `aria-live="polite"` region
- RTL: all logical properties (ps-/pe-/ms-/me-), `dir="rtl"` inherited from `<html>`
- Table columns do not reorder in RTL (# always first, actions always last per FRONTEND.md)
- Quantity inputs stay LTR for numeric entry in both locales
