# Phase 27: WhatsApp Integration

## Goal
WhatsApp is the primary communication channel for OTP delivery, order notifications, delivery confirmations, AR reminders, and CEO digest.

## Dependencies
- Phase 6 (Website Remaining -- login modal with OTP)
- Phase 11 (Portal Orders + Delivery)
- Phase 20 (Finance Module -- AR aging)
- Phase 23 (CEO Command Center -- digest)

## Requirements

- **INTG-01**: WhatsApp Cloud API: OTP delivery (with SMS/voice fallback cascade), order notifications, delivery confirmations, AR reminders, CEO digest, drop-ship POD flow, 7-day customer onboarding sequence, NPS survey (2h post-delivery)

## Success Criteria
1. OTP delivery via WhatsApp Cloud API succeeds with SMS fallback after 30s and voice after 60s
2. Order status notifications (confirmed, shipped, delivered) arrive on customer's WhatsApp
3. AR reminders send automatically based on aging thresholds
4. CEO daily digest (7AM) and weekly insight (Sunday) deliver via WhatsApp

## Spec References

### WhatsApp Cloud API Architecture

**Provider:** WhatsApp Cloud API (Meta direct, NOT Twilio). Cost: ~$50-150/mo.
**SMS fallback:** Twilio (SMS only): ~$80-150/mo.

### OTP Delivery (from RESEARCH.md)

**Egyptian SMS reliability below 85%. WhatsApp delivery: 99.5%.**

- **Primary:** WhatsApp OTP (not SMS). Fallback: SMS after 30s, voice call after 60s.
- **Carrier prefix detection:** +20 10x = Vodafone, +20 11x = Etisalat, +20 12x = Orange, +20 15x = WE (Telecom Egypt)
  - **Note:** WE/Telecom Egypt (+20 15x) is not explicitly listed in RESEARCH.md but is Egypt's fourth major carrier. This is a known spec gap -- RESEARCH.md only lists Vodafone, Etisalat, and Orange.
- OTP sent via WhatsApp Cloud API template message.
- If WhatsApp delivery not confirmed within 30 seconds: trigger SMS via Twilio.
- If SMS not confirmed within 60 seconds from initial request: trigger voice call via Twilio.

### Notification Cascade (from RESEARCH.md)

**WhatsApp first -> SMS fallback (if WhatsApp delivery fails) -> email fallback.** Never assume customer has WhatsApp.

**Notification channels by event type:**

### NPS Survey (from RESEARCH.md)

- Triggered 2 hours post-delivery via WhatsApp.
- 3 questions max:
  1. **NPS score:** 0-10 scale ("How likely are you to recommend HyperQuote?")
  2. **CSAT score:** 1-5 scale ("How satisfied were you with this delivery?")
  3. **Open text feedback:** Free-form comment
- Stored in `customer_feedback` table: `nps_score INTEGER (0-10)`, `csat_score INTEGER (1-5)`, `feedback_text TEXT`.
- Feeds into composite customer health score (15% weight).
- Detractor rescue within 24 hours.

### Drop-Ship POD Flow (from RESEARCH.md)

**Dual Confirmation:**
1. Supplier driver photographs signed HyperQuote delivery note -> sends via WhatsApp within 4 hours.
2. Customer confirms receipt via WhatsApp/portal ("Reply RECEIVED").
3. Invoice triggers on FIRST confirmation (don't wait for both).
4. Auto-confirm at 72 hours if dispatched but no confirmation or dispute.
5. Dispute window: 72 hours from dispatch.
6. Payment holdback: supplier not paid until POD uploaded (strongest enforcement lever).
7. Supplier POD compliance tracked in scorecard (below 80% = warning, below 70% = contract review).

**WhatsApp Business API integration:** Incoming WhatsApp messages to the dispatch number are routed to the customer service queue in the internal app. Media (photos) stored in Supabase Storage and linked to delivery record.

## Business Rules

**WhatsApp Template Messages:** All proactive messages to customers must use pre-approved WhatsApp template messages (Meta policy). Templates must be submitted and approved before use. Template categories: utility (OTP, delivery updates), marketing (onboarding sequence), authentication (OTP).

**Quiet Hours:** Respect customer notification preferences. No WhatsApp messages during configured quiet hours (e.g., 10PM-7AM). Urgent delivery notifications (driver arriving) may override.

**Work Week:** Sunday-Thursday. Weekend: Friday + Saturday. Adjust digest/insight delivery timing accordingly. CEO digest at 7AM Sunday-Thursday. Weekly insight at 6PM Friday (start of weekend).

**Ramadan Adjustments:** Reduced working hours (6h/day). Adjust delivery notification timing. SLA buffers extended.

**Friday Jumu'ah Blackout:** 11:30 AM - 1:30 PM. No delivery notifications during this window. Queue and send after 1:30 PM.

## Non-Negotiable Rules

1. **WhatsApp Cloud API (Meta direct), NOT Twilio for WhatsApp.** Twilio for SMS only.
2. **Cloudflare Workers** for webhook handlers and message sending.
3. **Bun, NOT npm/yarn/pnpm.**
4. **Arabic-Indic numerals** in Arabic WhatsApp messages. No exceptions.
5. **All amounts in Geist Mono** -- not applicable to WhatsApp text, but portal links must render correctly.
6. **EGP currency formatting:** "ج.م" suffix in Arabic, "EGP" prefix in English.

## Known Risks & Gotchas

1. **WhatsApp template approval:** Templates require Meta review. Submit early. Rejection means redesign and resubmit. Plan 1-2 week lead time.
2. **24-hour messaging window:** After customer initiates contact, you have 24 hours to send non-template messages. After 24h, only template messages allowed.
3. **Rate limiting:** WhatsApp Cloud API has tier-based rate limits. New business accounts start at Tier 1 (250 messages/day). Scale up by maintaining quality rating.
4. **Quality rating:** Too many blocks/reports from customers degrades your quality rating, reducing message limits. Ensure opt-in and relevance.
5. **Webhook reliability:** WhatsApp Cloud API webhooks must respond within 30 seconds. Use Cloudflare Queues for async processing.
6. **Media handling:** Photos from supplier POD flow arrive as WhatsApp media. Must download from Meta's CDN within 30 days.
7. **Carrier detection (+20 prefixes):** Not all numbers follow the simple prefix rule. Some numbers have been ported. Use as a hint, not a guarantee.
8. **SMS cost in Egypt:** International SMS to Egyptian numbers can be expensive. WhatsApp-first strategy is both cheaper and more reliable.

## Tips

- Implement the webhook handler first, then build message sending.
- Use Cloudflare Queues to decouple message sending from triggering events. Events publish to queue, Workers consume and send.
- Store all outbound message records in the database for audit trail.
- Template messages support variables: use {{1}}, {{2}} etc. for dynamic content (order numbers, amounts, names).
- Test with the WhatsApp Business Platform test number before going live.
- For the onboarding sequence, use pg_cron or Cloudflare Cron Triggers to schedule time-delayed messages.
- CEO digest: pre-compute all metrics in materialized views (ceo_attention_items etc.), then format as WhatsApp message.
