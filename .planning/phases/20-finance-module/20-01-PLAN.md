**types/finance.ts** — Define ALL finance domain types following warehouse.ts pattern:
- `FinanceTab = 'home' | 'invoicing' | 'ar' | 'ap' | 'payments' | 'credit' | 'recon' | 'reports'`
- Invoice: id, number, orderId, customerId, customerName, status (draft/sent/viewed/partially_paid/paid/overdue/collections/disputed/resolved/adjusted/written_off), etaStatus (pending/submitted/accepted/rejected/error), items (InvoiceItem[]), subtotal, vatAmount (14%), grandTotal, dueDate, issuedDate, currency ('EGP'), sellerTRN, buyerTRN, digitalSignatureId, pdfUrl, creditNoteIds
- InvoiceItem: id, productName, productNameAr, egsCode, uom, quantity, unitPrice, lineTotal, vatAmount
- ARAgingRow: customerId, customerName, tierBadge, current, days30, days60, days90, days90plus, total, sparklineData (number[]), salesRep
- ARAgingBucket: 'current' | '1-30' | '31-60' | '61-90' | '90+'
- Payment: id, invoiceId, amount, method (wire/cheque/lc/cash), reference, date, bankAccount, status, allocations (PaymentAllocation[])
- PaymentAllocation: invoiceId, amount
- ChequeRecord: id, chequeNumber, bankName, amount, maturityDate, drawerName, customerId, customerName, status (received/deposited/cleared/bounced/re_presented/written_off/replaced), linkedInvoiceId
- LetterOfCredit: id, lcNumber, issuingBank, amount, expiryDate, customerId, drawdowns (LCDrawdown[]), remainingAmount, documentChecklist (string[])
- LCDrawdown: id, amount, date, invoiceId
- APInvoice: id, supplierId, supplierName, poId, poNumber, amount, vatAmount, withholdingTax, netPayable, receivedDate, dueDate, matchStatus (matched/within_tolerance/exceeds_tolerance/unmatched), threeWayMatch (ThreeWayMatchResult)
- ThreeWayMatchResult: poLine (qty, price), receiptLine (qty), invoiceLine (qty, price), qtyVariance, priceVariance, withinTolerance
- CreditProfile: customerId, customerName, tier (1-5), creditLimit, currentExposure, utilizationPct, availableCredit, overdueAmount, paymentScore (0-100), avgDaysToPay, bouncedCheques12mo, lastPaymentDate, isOnHold, holdReasons (CreditHoldType[])
- CreditHoldType: 'limit_exceeded' | 'overdue_30' | 'overdue_pct' | 'bounced_cheque' | 'limit_expired'
- AutoHoldTrigger: type (CreditHoldType), threshold, currentValue, triggered
- BankTransaction: id, date, description, amount, reference, bankAccountId, reconStatus (matched/partially_matched/unmatched/exception), matchedPaymentId?
- ReconMatch: transactionId, paymentId, confidence (0-100), matchType ('exact' | 'partial' | 'manual')
- FinanceReport: id, name, type, dateRange, filters, generatedAt, downloadUrl
- CashFlowForecast: week, expectedInflows, expectedOutflows, netCash, cumulativeCash
- InvoiceDispute: id, invoiceId, invoiceNumber, customerId, customerName, reason, description, status (open/investigating/resolved/escalated), resolutionType? ('credit_note' | 'price_adjustment' | 'write_off' | 'no_action'), assignedTo?, createdAt, resolvedAt?, slaDeadline, evidenceUrls
- FinanceDashboard: revenueMTD, outstandingAR, overdueAR, cashPosition, dso, cei, arAging ({current, days30, days60, days90, days90plus}), expectedPaymentsThisWeek, paymentMethodBreakdown, topCreditUtilization, apDueThisWeek, overdueAP, avgMarginMTD

- Valid transitions: received->deposited, deposited->cleared, deposited->bounced, bounced->re_presented, bounced->written_off, bounced->replaced, re_presented->cleared, re_presented->bounced

- canTransition(from, to): boolean
- transitionCheque(cheque, newStatus, reason?): { success, cheque?, error? }
