**PaymentFlow.tsx** — Step wizard container (Section 5.4):
- Reads paymentFlow from useFinanceStore (step, method)
- Steps: 1) Select Method -> 2) Enter Details -> 3) Allocate to Invoices -> 4) Confirm
- Step indicator at top (numbered circles connected by line, active step highlighted blue)
- Renders appropriate component per step: MethodSelector (step 1), WireTransferForm/ChequeForm/LCForm/CashForm (step 2 based on method), InvoiceAllocator (step 3), PaymentConfirmation (step 4)
- Back/Next navigation, Cancel resets flow

**MethodSelector.tsx** — Step 1 (Section 5.4):
- 4 clickable cards in a 2x2 grid: Wire Transfer (bank icon), Cheque (document icon), Letter of Credit (shield icon), Cash (banknote icon)
- Each card: icon, title, brief description
- Click sets method in store and advances to step 2
- Per FIN-03: all 4 payment instruments must be present (wire, cheque, LC, cash)

**WireTransferForm.tsx** — Step 2 for wire (Section 5.4):
- React Aria fields: Bank reference number (TextField), Amount received (NumberField, Geist Mono), Date received (DatePicker), Receiving bank account (Select dropdown)
- [Match to Invoice] button — calls autoMatchPayment from matching.ts
- Auto-suggests matching invoices based on customer + amount + memo
- If exact match found: shows matched invoice with green highlight, one-click confirm
- If no exact match: proceeds to manual allocation

**CashForm.tsx** — Step 2 for cash (per FIN-03 requiring all 4 instruments):
- React Aria fields: Amount received (NumberField, Geist Mono), Date received (DatePicker), Reference/receipt number (TextField, optional), Received by (TextField — name of person who collected cash)
- Info banner: "Cash payments require physical receipt. Ensure receipt number is recorded for audit trail."
- Form validation: amount required, date required
- On submit: advances to InvoiceAllocator (step 3) with method='cash'
- Follows same flow as wire/cheque/LC: CashForm -> InvoiceAllocator -> PaymentConfirmation

**InvoiceAllocator.tsx** — Step 3 (shared across all 4 methods):
- List of customer's invoices with checkboxes
- Each row: Invoice #, Amount, Due Date, Status
- Running balance bar at top (sticky): "Payment Amount: EGP 247,500 -- Applied: EGP 247,500 = Remaining: EGP 0"
- All amounts in Geist Mono. Balance updates live as checkboxes toggle.
- [Auto-allocate FIFO] button: checks invoices oldest-first until payment exhausted
- Partial allocation: if payment doesn't cover full invoice, shows partial amount input
- Overpayment handling: if Remaining > 0 after all invoices, show 3 options: [Apply to Next Invoice] [Hold as Credit] [Initiate Refund]
- Colors: Remaining = 0 -> green bar, Remaining > 0 -> yellow bar

Wire PaymentFlow into FinanceModule for 'payments' tab.
