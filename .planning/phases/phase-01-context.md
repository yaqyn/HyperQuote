# Phase 1: Monorepo Scaffold

## Goal
Every app and package builds and runs from a single monorepo, with Supabase SSR on Workers validated as feasible.

## Dependencies
Nothing (first phase).

## Requirements

- **FOUND-01**: Monorepo scaffold with 5 apps + 7 shared packages builds and runs (`bun install` + `bun run dev`)
- **FOUND-03**: Supabase SSR auth works on Cloudflare Workers (go/no-go validation with `nodejs_compat`)
- **FOUND-04**: TanStack Start SSR renders a page with server function data on Cloudflare Workers

## Success Criteria
1. `bun install` succeeds at monorepo root and all workspaces resolve
2. `bun run dev --filter=website` starts TanStack Start and renders a page with server function data
3. Supabase SSR auth creates and reads a session cookie on Cloudflare Workers (with `nodejs_compat`)
4. Each of the 5 apps has a working dev server (4 TanStack Start + 1 plain Vite for driver)

## What to Build
- Root `package.json` with Bun workspaces
- `turbo.json` for parallel builds
- Each app: `package.json` + `vite.config.ts` + `tsconfig.json`
- TanStack Start entry files for website/portal/internal/ceo (`router.tsx`, `client.tsx`, `routes/__root.tsx`)
- Driver app: plain Vite config (no tanstackStart, no cloudflare)
- Each shared package: `package.json` + `tsconfig.json` + `src/index.ts` barrel export
- `.biome.json` + `.eslintrc` (hooks only) + `lefthook.yml`
- Supabase SSR go/no-go test on Workers

### TanStack Start Entry Points (v1.121.0+)
**Source directory:** `src/` is the default. NEVER override with `srcDirectory: 'app'`.

| File | Purpose | Required? |
|------|---------|-----------|
| `router.tsx` | Exports `getRouter()` (internally calls `createRouter`) | Yes |
| `client.tsx` | `<StrictMode><StartClient /></StrictMode>` (no props) | Optional (has default) |
| `server.ts` | Custom server entry (fetch handler) | Optional (has default) |
| `routeTree.gen.ts` | Auto-generated by TanStack Router | Auto |
| `routes/__root.tsx` | Root route with `<HeadContent />` + `<Scripts />` | Yes |

### Vite Config (Cloudflare Workers)
```tsx
import { defineConfig } from 'vite'
import { cloudflare } from '@cloudflare/vite-plugin'
import { tanstackStart } from '@tanstack/react-start/plugin/vite'
import tailwindcss from '@tailwindcss/vite'
import react from '@vitejs/plugin-react'

export default defineConfig({
  plugins: [
    cloudflare({ viteEnvironment: { name: 'ssr' } }),
    tailwindcss(),
    tanstackStart(), // src/ is the default — NEVER override with srcDirectory
    react(),         // Must come AFTER tanstackStart()
  ],
})
```

## Non-Negotiable Rules
1. **TanStack Start, NOT Next.js.** Use `@tanstack/react-start` (v1.167.12+). NOT `@tanstack/start` (frozen). NOT Next.js. NOT Remix.
2. **Bun, NOT npm/yarn/pnpm.** Use `bun add`, `bun run`, `bun install`.
3. **Cloudflare Workers, NOT Vercel/Netlify.** Deploy target is always Cloudflare Workers. Use `@cloudflare/vite-plugin`.
4. **Colors in `:root {}`, NEVER in `@theme`.** Tailwind v4 critical: `--color-*` in `@theme` collides with built-in utilities.

## Known Risks & Gotchas

### CRITICAL: Supabase SSR on Cloudflare Workers (HIGHEST RISK)
`@supabase/ssr` internally requires Node.js `stream` module. Workers is a V8 isolate, not Node.js. This causes `"dynamic require of 'stream' is not supported"` at runtime. Documented in supabase/supabase#37592.
- **Mitigation:** Enable `nodejs_compat` compatibility flag in `wrangler.jsonc`. Test Day 1. If it still fails: create a thin wrapper using `@supabase/supabase-js` directly with manual cookie parsing.
- **Warning signs:** Build succeeds but runtime throws 500. Auth works in `bun run dev` but fails on deployed Workers.

### CRITICAL: Vite 8 Not Ready
TanStack Start reports "not responding" on Vite 8. Stay on Vite 7.3.1. Do NOT upgrade.

### CRITICAL: TanStack Start vinxi removal (v1.121.0+)
`vinxi` removed. Use `vite dev`/`vite build`. Only `@tanstack/react-start` needed. Do NOT install `vinxi`.

### HIGH: Plugin Order Matters
In vite.config.ts: cloudflare -> tailwindcss -> tanstackStart -> react. Wrong order causes silent failures.

### HIGH: Import Boundary Violations
Server-only imports (`cloudflare:workers`, Supabase admin client) leak into client bundle. NEVER import `cloudflare:workers` at top of route files. Only inside server function bodies or `.server.ts` files.

### MEDIUM: React Aria I18nProvider SSR Hydration Bug (#7474)
`useDefaultLocale()` causes blank page flash in TanStack Start SSR. Pass locale explicitly to `I18nProvider` or wrap in `ClientOnly`.

### MEDIUM: Router Export Renamed
Export `getRouter()` which internally calls `createRouter()`. `StartClient` takes no props.

### LOW: `ssr.tsx` Obsolete
Delete `ssr.tsx`. TanStack Start uses default server entry.

### LOW: i18next Version Discrepancy
CLAUDE.md notes i18next should be updated from ^25.10.10 to ^26.0.1. Breaking change: `interpolation.format` API removed. Verify no usage of this API in Phase 3.

### LOW: 100+ Routes Slow Vite Dev
Use TanStack Router lazy imports, code-split route tree.

## Tips
- Use `@tanstack/react-start` NOT `@tanstack/start` (frozen)
- Plugin order matters: cloudflare -> tailwindcss -> tanstackStart -> react
- Do NOT install vinxi
- Driver app has its own vite config without tanstackStart() or cloudflare()
- Use `bun run` not `npx` -- 10x faster
- Use Turborepo `--filter` to build only what changed
- Test production builds (`vite build`) frequently -- dev mode hides import issues
