  <action>
    **CycleCountList.tsx** — List of assigned counts:
    - Fetch via TanStack Query (`getCycleCountAssignments`)
    - Each card: location code, count number / total (Geist Mono), status badge (assigned/counting/submitted/recount_requested/approved)
    - Filter by status
    - Tap card -> setSelectedCountId -> navigate to BlindCountEntry (if assigned/counting) or CountReview (if submitted) or SupervisorApproval (if recount_requested)
    - StepIndicator showing "Count X of Y" for assigned counts

    **BlindCountEntry.tsx** — Per spec section 4.9, CRITICAL blind count:
    - Fetch assignment via TanStack Query with SEPARATE query key `['cycleCount', 'assignment', countId]` — NEVER shares cache with inventory queries (per Pitfall 1)
    - Call `getCycleCountAssignment({ countId })` which returns ONLY: locationCode, items[{ productId, productName, sku, lotNumber }]
    - **System quantity is HIDDEN. Worker does NOT see expected count. This prevents bias.**
    - Step 1: `[Scan Location to Start]` — ScanInput to confirm worker is at correct location
    - Step 2: Per product at this location:
      - Product name and SKU displayed
      - Physical count input (LargeNumberInput, Geist Mono) — large 64dp input for glove use
      - NO system quantity visible anywhere on screen
    - `[+ Add Unexpected Product]` button: for items found at location but not in system. Opens a form: ScanInput for product barcode, product name input, physical count.
    - `[Submit Count]` button — calls `submitCycleCount` server function, navigates to CountReview
    - All interactive elements minimum 48dp, number inputs 64dp

    **CountReview.tsx** — After submission, system reveals comparison:
    - Data from `submitCycleCount` response (CycleCountResult[])
    - Per product row:
      - Product name, SKU
      - System qty (Geist Mono) — NOW revealed
      - Worker count (Geist Mono)
      - Variance = workerCount - systemQty (Geist Mono)
      - Variance % (Geist Mono, VarianceBadge component for color)
    - ABC class shown per product (from result)
    - Threshold check result: "Within threshold — auto-approved" (green) or "Exceeds threshold — recount requested" (red)
    - If ANY item needsRecount: show banner "Recount requested — will be assigned to a different worker" (per spec: different worker for objectivity)
    - If all within threshold: "Count approved automatically" with green confirmation
    - `[Back to Count List]` button

    **SupervisorApproval.tsx** — Manager reviews variance:
    - Fetch SupervisorApproval data via server function
    - Display:
      - Location, product name
      - System qty, initial count, recount qty — all Geist Mono
      - Variance and variance % (VarianceBadge)
      - Recent movements list (StockMovement[]) for investigation — shows type, quantity (Geist Mono), timestamp (Geist Mono), reference
      - Financial impact: value of adjustment in EGP (Geist Mono, CurrencyDisplay)
    - Reason code select (React Aria Select): Receiving error, Pick error, Damage (unrecorded), Theft, Miscount, Location error
    - `[Approve]` button — calls `submitCycleCountApproval({ decision: 'approve', reason })`
    - `[Investigate Further]` button — calls `submitCycleCountApproval({ decision: 'investigate' })`
  </action>
