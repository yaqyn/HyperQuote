  <action>
    **LoadVerification.tsx** — Per spec section 4.8, 5-step gated flow on tablet:

    Use React Hook Form for the entire verification form. Track current step via useWarehouseStore.activeWorkflow for persistence. Use GatedStep for each step.

    **Step 1 — Scan truck ID:**
    - ScanInput with truck ID barcode
    - `canAdvance`: truck scanned successfully
    - Display: truck ID, assigned route

    **Step 2 — Scan items onto truck:**
    - Progress bar: "18 of 22 scanned" (Geist Mono)
    - Remaining items checklist with ScanInput per item
    - Each scanned item shows green checkmark
    - `canAdvance`: all items scanned (totalItems === itemsScanned)

    **Step 3 — Verify weight on scale:**
    - Expected weight (Geist Mono, from staging plan total)
    - Actual weight input (LargeNumberInput, Geist Mono)
    - Auto-calculated variance with useWatch(): display as "Expected: 18,500 kg | Actual: 18,340 kg | Variance: 0.9%"
    - Color coding: GREEN = within tolerance (configurable, default 2%), YELLOW = 2-5%, RED = >5%
    - `canAdvance`: weight entered AND variance within tolerance (or manager override active). Weight tolerance is NOT hardcoded — read from a TOLERANCE_CONFIG object (per locked decision: weight verification tolerance is configurable).

    **Step 4 — Capture photos:**
    - Three PhotoCapture instances: `[Rear Photo]` `[Side Photo]` `[Seal Photo]`
    - Each shows thumbnail preview after capture
    - Minimum required photos configurable (default: all 3 required)
    - `canAdvance`: minimum required photos captured

    **Step 5 — Sign-off:**
    - Two SEPARATE SignaturePad instances (per locked decision: dual signature pad requires two separate components):
      - "Driver Signature" — driver signs first
      - "Loader Signature" — loader signs second
    - `[Gate Clearance]` button (only enabled when both signatures captured)
    - `canAdvance`: both signatures captured

    **Hard gating** — After all 5 steps, check for blocks:
    - Missing items (not all scanned) -> BLOCKED
    - Weight variance > tolerance -> BLOCKED
    - Required photos missing -> BLOCKED
    - If ANY block: show `[BLOCKED - Resolve Issues]` in red with list of block reasons. Manager override button opens React Aria Dialog (with `isKeyboardDismissDisabled`) requiring manager credentials + reason.
    - If NO blocks: show `[Generate BOL]` button (placeholder — actual PDF generation deferred to Phase 28). On click: call `loadVerification` server function, show success confirmation, navigate back to staging list.

    On clearance: display success message "Gate clearance granted — BOL will be generated". The actual triggers (outbound inventory state change, delivery tracking activation, customer notification) are server-side.
  </action>
