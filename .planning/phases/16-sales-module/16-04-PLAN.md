    - Missing: dash + "No Price Available"

    **MarginGuardrails.tsx** -- Step 4: Per-line margin indicator:
    - Props: `marginPercent: number, thresholds: MarginThresholds`
    - Uses `getMarginLevel(marginPercent, thresholds)` from types/sales.ts.
    - Renders colored bar/indicator next to margin cell:
      - Green (>= target): checkmark icon
      - Yellow (>= floor, < target): warning icon + "Below target"
      - Red (>= absoluteMin, < floor): alert icon + "Manager approval required"
      - Blocked (< absoluteMin or negative): stop icon + "CEO Approval Required" or "Negative margin -- cannot save"
    - Thresholds fetched from `getQuoteBuilderData` (pricing_rules table), NOT hardcoded.
    - Colors are data-semantic only (green/yellow/red on the indicator, not on surrounding UI).

    **MarginControlPanel.tsx** -- Right sidebar:
    - Shows overall blended margin (weighted average across all line items).
    - Target margin vs actual (Geist Mono, with colored indicator).
    - Floor margin display.
    - Approval status: "Auto-approved" (green) or "Needs Manager Approval" (yellow) or "Needs CEO Approval" (red).
    - Quick adjust buttons: "Set all to 15%", "Set all to 18%", "Set all to 20%".
    - What-if calculator: slider or input to test different blanket margins, shows resulting total and profit.
    - All numbers in Geist Mono.

    **ApprovalWorkflow.tsx** -- Step 8:
    - Determines approval routing per CONTEXT.md thresholds:
      - Margin >= target: no approval needed (auto-approved)
      - Margin >= floor < target: Sales Manager approval
      - Margin < floor: VP Sales approval
      - Margin < absoluteMin: CEO approval
      - Value < EGP 2.5M: Rep authority. 2.5-10M: + Sales Manager. 10-50M: + Director. > 50M: + CEO.
    - Highest required approval wins (margin + value combined).
    - Shows approval chain visually: list of required approvers.
    - "Request Approval" button calls `requestApproval` mutation.
    - Rep can add urgency note and justification before submitting.
    - After submission: status changes to "Pending Approval", shows waiting state.
    - Escalation info: "If not approved within 2h, escalates to [next level]".
    - Approver gets one-click actions (Approve, Reject, Request Changes) -- rendered if current user IS the approver.
