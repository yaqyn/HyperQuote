**Pool & Identity Extractors (functions 1-8):**
1. `get_user_pool()` RETURNS TEXT -- reads `auth.jwt()->'app_metadata'->>'pool'`, defaults to `'external'`
2. `is_internal_user()` RETURNS BOOLEAN -- calls `get_user_pool() = 'internal'`
3. `is_external_user()` RETURNS BOOLEAN -- calls `get_user_pool() = 'external'`
4. `current_tenant_id()` RETURNS UUID -- reads `auth.jwt()->'app_metadata'->>'tenant_id'`, casts to UUID
5. `current_user_type()` RETURNS TEXT -- reads `auth.jwt()->'app_metadata'->>'user_type'`, defaults to `'unknown'`
6. `current_customer_id()` RETURNS UUID -- reads `auth.jwt()->'app_metadata'->>'customer_id'`
7. `current_supplier_id()` RETURNS UUID -- reads `auth.jwt()->'app_metadata'->>'supplier_id'`
8. `current_driver_id()` RETURNS UUID -- reads `auth.jwt()->'app_metadata'->>'driver_id'`

All 8 are `LANGUAGE sql STABLE`.

**Role & Permission Checkers (functions 9-10):**
9. `has_role(required_role TEXT)` RETURNS BOOLEAN -- checks JWT `app_metadata->'roles'` array via `jsonb_array_elements_text`. `LANGUAGE sql STABLE`.
10. `authorize(requested_permission app_permission)` RETURNS BOOLEAN -- `LANGUAGE plpgsql STABLE SECURITY DEFINER SET search_path = public`. Queries `role_permissions` table joining on JWT roles array. Uses `app_permission` type for the parameter.

**Trigger Functions (functions 11-12):**
11. `set_tenant_id()` RETURNS TRIGGER -- `LANGUAGE plpgsql SECURITY DEFINER SET search_path = public`. Sets `NEW.tenant_id` from `current_tenant_id()`, raises exception if NULL.
12. `update_updated_at()` RETURNS TRIGGER -- `LANGUAGE plpgsql`. Sets `NEW.updated_at = NOW()`.

**Trigger Attachments** (at the bottom of this migration, after functions are defined):
```sql
-- updated_at triggers
```

Note: Do NOT attach set_tenant_id to `tenants` table itself (tenant creation is a special admin operation, not auto-populated from JWT).

**1. Create `supabase/migrations/20260331000005_access_token_hook.sql`:**

The hook function exactly as in CONTEXT.md with these critical details:
- `LANGUAGE plpgsql STABLE SECURITY DEFINER SET search_path = public`
- Queries `user_profiles` using `WHERE p.user_id = custom_access_token_hook.user_id` (NOT `WHERE p.id = user_id` which is the BACKEND.md bug)
- Selects `p.pool, p.user_type, p.tenant_id, p.customer_id, p.supplier_id, p.driver_id` from user_profiles
- Queries `user_roles` for role array using `WHERE ur.user_id = custom_access_token_hook.user_id`
- Builds JWT claims with: pool, user_type, tenant_id, roles (jsonb array), customer_id, supplier_id, driver_id
- Returns unmodified event if user_profile NOT FOUND

Grants (CRITICAL for auth to work):
```sql
GRANT EXECUTE ON FUNCTION public.custom_access_token_hook TO supabase_auth_admin;
REVOKE EXECUTE ON FUNCTION public.custom_access_token_hook FROM PUBLIC;
REVOKE EXECUTE ON FUNCTION public.custom_access_token_hook FROM anon;
REVOKE EXECUTE ON FUNCTION public.custom_access_token_hook FROM authenticated;
```

Grant `supabase_auth_admin` SELECT on the tables the hook reads:
```sql
GRANT SELECT ON public.user_profiles TO supabase_auth_admin;
GRANT SELECT ON public.user_roles TO supabase_auth_admin;
```
