**useLoginModal.ts (Zustand store):**
```typescript
import { create } from 'zustand'

type LoginStep = 'phone' | 'otp' | 'create' | 'claiming'

interface LoginModalState {
  isOpen: boolean
  step: LoginStep
  phone: string
  redirectTo: string | null
  claimableCompany: string | null
  open: (redirectTo?: string) => void
  close: () => void
  setStep: (step: LoginStep) => void
  setPhone: (phone: string) => void
  setClaimableCompany: (company: string | null) => void
  reset: () => void
}

export const useLoginModal = create<LoginModalState>((set) => ({
  isOpen: false,
  step: 'phone',
  phone: '',
  redirectTo: null,
  claimableCompany: null,
  open: (redirectTo) => set({ isOpen: true, step: 'phone', phone: '', redirectTo: redirectTo ?? null, claimableCompany: null }),
  close: () => set({ isOpen: false }),
  setStep: (step) => set({ step }),
  setPhone: (phone) => set({ phone }),
  setClaimableCompany: (company) => set({ claimableCompany: company }),
  reset: () => set({ isOpen: false, step: 'phone', phone: '', redirectTo: null, claimableCompany: null }),
}))
```

**auth.ts (5 server functions):**
All use `createServerFn()` with `.inputValidator()` and `{ data: input }` destructuring. Follow the exact pattern from catalog.ts.

1. `sendOTP`: Input `{ phone: z.string().regex(/^(10|11|12|15)\d{8}$/), method: z.enum(['whatsapp', 'sms']) }`. Handler: format phone as `+20${input.phone}`, call `supabase.auth.signInWithOtp({ phone: formattedPhone, options: { channel: input.method } })`. Return `{ success: true, expiresIn: 300 }` or error. For dev: if Supabase OTP not configured, return mock success.

2. `verifyOTP`: Input `{ phone: phoneSchema, code: z.string().length(6).regex(/^\d{6}$/) }`. Handler: call `supabase.auth.verifyOtp({ phone: `+20${input.phone}`, token: input.code, type: 'sms' })`. On success: query `customers` table for phone match. Return `{ success, session, user, needsAccount: boolean, claimableCompany: string | null }`.

3. `createAccount`: Input `{ phone: phoneSchema, companyName: z.string().min(1).max(200), fullName: z.string().min(1).max(100) }`. Handler: insert into `customers` table (mock for now), link to auth user. Return `{ customerId, userId }`.

4. `claimAccount`: Input `{ phone: phoneSchema }`. Handler: match phone to unclaimed customer, link auth user. Return `{ customerId, claimed: true }`.

5. `signOut`: No input. Handler: call `supabase.auth.signOut()`. Return `{ success: true }`.

All server functions create Supabase client via `createSupabaseServerClient` from `@hyperquote/auth/server` using `getRequest()` for the request context. Use try/catch with error returns, never throw.

Structure:
```tsx
// AnimatePresence wraps the conditional render
<AnimatePresence>
  {isOpen && (
    <ModalOverlay
      isDismissable
      isOpen={isOpen}
      onOpenChange={(open) => { if (!open) close() }}
      className="fixed inset-0 z-50 flex items-center justify-center bg-black/50 backdrop-blur-[4px]"
    >
      <Modal className="outline-none">
        <Dialog className="outline-none">
          <motion.div
            initial={{ scale: 0.95, opacity: 0 }}
            animate={{ scale: 1, opacity: 1 }}
            exit={{ opacity: 0 }}
            transition={{
              type: 'spring',
              stiffness: 260,
              damping: 20,
            }}
            // Exit is tween 150ms:
            // exit transition overridden below
            className="bg-[var(--color-card)] rounded-2xl max-w-[440px] w-full mx-4 shadow-xl p-8"
          >
            {step === 'phone' && <PhoneStep />}
            {step === 'otp' && <OTPStep />}
            {step === 'create' && <AccountCreation />}
            {step === 'claiming' && <AccountClaiming />}
          </motion.div>
        </Dialog>
      </Modal>
    </ModalOverlay>
  )}
</AnimatePresence>
```

CRITICAL notes:
- Spring enter: scale 0.95->1, opacity 0->1, stiffness 260, damping 20.
- Tween exit: opacity 1->0, 150ms. Use `exit={{ opacity: 0 }}` with `transition` on the exit variant.
- `isKeyboardDismissDisabled` is NOT set (per CLAUDE.md this is for Dialogs — the login modal IS dismissable).
- Wait, CLAUDE.md says `isKeyboardDismissDisabled` on Dialogs. But CONTEXT.md says `isDismissable={true}`. The CONTEXT.md takes precedence — the modal IS dismissable. Do NOT set `isKeyboardDismissDisabled`.
- Focus is trapped by React Aria Modal automatically.
- Mobile (<480px): `max-w-full mx-4 rounded-xl` (no rounded-2xl on very small screens).
